Project Detail

Hater

Unity WebGL 게임을 웹 서비스로 제공하기 위해 React 웹 포털, 인증/세션 흐름, GitLab CI/CD, Docker/Nginx/AWS 배포 환경을 구축한 웹 게임 플랫폼 프로젝트입니다.

  • 2026.04 ~ 2026.05
  • Frontend · Infra · CI/CD
  • React · TypeScript · Unity WebGL
  • Docker · Nginx · AWS · GitLab CI/CD

Overview

Hater는 Unity WebGL 기반의 중세 디펜스 게임을 웹 브라우저에서 별도 설치 없이 플레이할 수 있도록 만든 웹 게임 플랫폼입니다. 사용자는 웹 포털에서 게임 정보를 확인하고, 로그인 후 게임에 진입하며, 랭킹과 마이페이지, 피드백, 뉴스 영역을 통해 서비스 형태로 게임을 이용할 수 있습니다.

저는 React 웹 포털 전체 구현과 배포 인프라, CI/CD 파이프라인 구성을 담당했습니다. 단순히 Unity WebGL 빌드를 실행하는 페이지를 만드는 것이 아니라, 사용자가 게임을 탐색하고 인증 상태를 유지하며 안정적으로 플레이에 진입할 수 있는 웹 서비스 흐름을 구축하는 데 집중했습니다.

My Role & Scope

  • React와 TypeScript 기반으로 홈, 게임 목록, 게임 상세, 랭킹, 마이페이지, 피드백, 뉴스 등 웹 포털 전반을 구현했습니다.
  • 이메일 인증, 비밀번호 찾기, 로그아웃 확인 모달, 게임 플레이 진입 전 세션 검증 등 사용자 인증 흐름을 구성했습니다.
  • 웹게임 이용 중 세션이 끊기지 않도록 토큰 리프레시 로직과 Heartbeat/Ping 기반 온라인 상태 확인 흐름을 적용했습니다.
  • GitLab CI/CD에서 변경된 영역만 선택적으로 배포하는 부분 배포 로직을 설계하고, Kaniko 기반 Docker 이미지 빌드와 Docker Compose 배포 환경을 구성했습니다.
  • AWS S3 기반 Unity WebGL 정적 파일 서빙과 자동 업로드 파이프라인, CloudFront 캐시 전략, Nginx 도메인 리다이렉트, Prometheus 기반 Spring 메트릭 수집을 함께 다뤘습니다.

Architecture Focus

  • React 웹 포털은 게임 진입 전 필요한 서비스 화면과 인증 상태를 담당하고, Unity WebGL 빌드는 S3에 업로드해 정적 리소스로 제공할 수 있도록 구성했습니다.
  • Spring Boot API 서버는 인증, 사용자 정보, 랭킹, 피드백 등 서비스 데이터를 처리하며, PostgreSQL과 Redis를 함께 사용했습니다.
  • Docker Compose 기반 실행 환경과 GitLab CI/CD를 연결해 프론트엔드, 백엔드, WebGL 리소스를 반복적으로 빌드/배포할 수 있는 흐름을 만들었습니다.

Problem & Solution

첫 번째 문제는 Unity WebGL 게임을 일반 웹 서비스 안에 자연스럽게 포함하는 것이었습니다. WebGL 빌드는 일반 React 페이지와 달리 .wasm, .data, .framework.js 같은 정적 리소스를 포함하고 있어 실행 경로와 캐시 전략이 중요했습니다. 이를 해결하기 위해 WebGL 실행 경로를 빌드 환경변수로 분리하고, S3 자동 업로드 파이프라인과 CloudFront 캐시 전략을 함께 검토했습니다.

두 번째 문제는 웹게임 플레이 중 인증 상태를 안정적으로 유지하는 것이었습니다. 사용자가 게임에 진입한 뒤 토큰이 만료되거나 세션이 유효하지 않으면 플레이 경험이 끊길 수 있었습니다. 이를 줄이기 위해 게임 진입 전 세션 검증을 적용하고, 토큰 리프레시와 Heartbeat/Ping 기반 온라인 상태 확인 흐름을 구성했습니다.

세 번째 문제는 짧은 프로젝트 기간 안에서 여러 구성 요소를 안정적으로 배포하는 것이었습니다. 프론트엔드, 백엔드, WebGL 리소스가 함께 관리되어야 했기 때문에 GitLab CI/CD에서 변경된 컴포넌트만 선택적으로 재배포하는 부분 배포 로직을 설계하고, Kaniko 이미지 빌드와 Docker Compose 배포 환경을 구성했습니다.

네 번째 문제는 서비스 운영 관점의 가시성을 확보하는 것이었습니다. Prometheus와 Spring 메트릭 수집을 연결해 단순 실행 여부를 넘어 백엔드 상태를 관찰할 수 있는 기반을 마련했습니다.

Technical Highlights

  • React/TypeScript 기반으로 홈, 게임 목록, 게임 상세, 랭킹, 마이페이지, 피드백, 뉴스 등 웹 포털 전체 화면을 구현했습니다.
  • 이메일 인증, 비밀번호 찾기, 로그아웃 확인 모달, 게임 진입 전 세션 검증 등 사용자 인증 UX를 구성했습니다.
  • Heartbeat/Ping 로직과 토큰 리프레시 흐름을 적용해 웹게임 이용 중 세션 유지 경험을 개선했습니다.
  • GitLab CI/CD에서 변경 파일 기준 부분 배포 로직을 설계해 프론트엔드, 백엔드, WebGL 리소스를 선택적으로 배포할 수 있도록 구성했습니다.
  • Kaniko를 활용해 Docker daemon에 의존하지 않는 이미지 빌드 흐름을 구성하고, docker-compose.deploy.yml 기반 초기 배포 환경과 환경변수 주입 방식을 정리했습니다.
  • AWS S3에 Unity WebGL 빌드 결과물을 업로드하는 자동 배포 파이프라인을 구성하고, CloudFront 연동과 WebGL 버전별 캐시 전략을 검토했습니다.
  • Nginx 도메인 리다이렉트, WebGL 실행 경로 분리, 모바일 반응형 CSS, favicon 설정, Prometheus 기반 Spring 메트릭 수집을 수행했습니다.

Result & Retrospective

2026년 5월 13일 데모 버전, 5월 18일 정식 버전, 5월 20일 2.0.0 업데이트까지 이어지는 릴리즈를 완료했습니다. 단순 구현에서 끝나지 않고 인증 흐름, WebGL 리소스 제공, API 연동, 배포 자동화, 모니터링 기반까지 실제 서비스 운영 흐름 안에서 연결했습니다.

이 프로젝트를 통해 Unity WebGL 게임을 실행 가능한 빌드 파일로 제공하는 것과 실제 웹 서비스처럼 운영하는 것은 다른 문제라는 점을 경험했습니다. 게임을 서비스로 제공하려면 React 웹 포털, 인증/세션 흐름, WebGL 정적 리소스 제공, API 서버, 도메인, 캐시, 배포 자동화, 모니터링이 하나의 흐름으로 연결되어야 한다는 점을 배웠습니다.
