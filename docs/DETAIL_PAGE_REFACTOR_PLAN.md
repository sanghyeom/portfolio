# Detail Page Refactor Plan

작성일: 2026-05-17

적용일: 2026-05-17

## 적용 현황

이 문서의 리팩터링 방향을 기준으로 1차 작업을 반영했습니다.

- 상세 페이지 공통 레이아웃 SCSS 추가
- `project-detail-layout`, `project-detail-main`, `project-detail-sidebar` 구조 적용
- 긴 본문은 `Overview / My Role / Problem & Solution / Result` 흐름으로 정리
- 요약 정보, 기술 스택, 링크는 오른쪽 사이드바 패널로 분리
- DDIB, Mannequin, Pollin, Gridsol SCADA 상세 페이지에 동일한 구조 적용
- `npm run build` 검증 완료
- 개발 서버에서 4개 상세 페이지 `200 OK` 응답 확인

확인 URL:

- `http://localhost:60191/projects/ddib/`
- `http://localhost:60191/projects/mannequin/`
- `http://localhost:60191/projects/pollin/`
- `http://localhost:60191/career/Gridsol_SCADA/`

## 결론

현재 디테일 페이지는 정보 전달은 충분히 되지만, 메인 페이지와 비교하면 별도의 템플릿처럼 보이는 부분이 있습니다.

리팩터링은 가능합니다. 현재 프로젝트가 정적 HTML과 SCSS 기반이라 큰 구조 변경 없이도, 메인 페이지와 더 잘 어울리는 상세 페이지로 정리할 수 있습니다.

핵심 방향은 다음입니다.

- 메인 페이지의 차분한 흰 배경, 얇은 보더, 둥근 기술 스택 칩 스타일 유지
- 상세 페이지의 카드 남발을 줄이고 정보 흐름을 더 명확하게 구성
- 프로젝트별 설명 깊이는 유지하되, 채용 담당자가 빠르게 훑을 수 있는 구조로 개선
- 모든 상세 페이지가 같은 레이아웃 규칙을 공유하도록 SCSS 정리

## 현재 레이아웃 진단

### 좋은 점

- 프로젝트별 상세 페이지가 이미 분리되어 있어 확장하기 쉽습니다.
- 히어로 영역에 제목, 요약, 기간, 역할, 기술이 있어 첫 화면에서 기본 맥락을 파악할 수 있습니다.
- 기술 스택 컴포넌트가 메인 페이지와 상세 페이지에서 같은 클래스를 쓰기 시작해 스타일 통일 기반이 생겼습니다.
- DDIB처럼 갤러리가 있는 프로젝트는 실제 화면을 보여줄 수 있어 설득력이 있습니다.

### 아쉬운 점

- 상세 페이지 배경과 카드 스타일이 메인 페이지보다 더 장식적인 느낌입니다.
- 대부분의 정보가 큰 카드 단위로 나뉘어 있어, 읽는 흐름이 조금 끊깁니다.
- 프로젝트별 상세 페이지의 정보 밀도와 구성 방식이 서로 다릅니다.
- `기여 내용`, `사용 기술`, `핵심 포인트`, `결과`가 페이지마다 다른 위치와 형태로 나타납니다.
- 메인 페이지에서 이어지는 "프로젝트 카드 -> 상세 설명"의 시각적 연결감이 약합니다.

## 추천 리팩터링 방향

### 1. 상세 페이지 히어로 재구성

현재:

- 왼쪽: 제목, 요약, 메타 정보, 버튼
- 오른쪽: 대표 이미지

추천:

- 상단에 돌아가기 링크 유지
- 제목 영역은 더 간결하게 구성
- 프로젝트 한 줄 요약을 강조
- 기간, 역할, 핵심 기여는 작은 메타 바 형태로 정리
- 대표 이미지는 카드 느낌을 줄이고, 메인 페이지 썸네일과 비슷한 그림자/라운드 기준으로 통일

예상 변경:

- `.project-detail-hero`
- `.project-detail-hero__grid`
- `.project-detail-meta`
- `.project-detail-hero__media`

### 2. 본문 구조를 공통 섹션으로 정리

상세 페이지마다 아래 순서를 기본으로 맞추는 것을 추천합니다.

1. Overview
2. My Role
3. Problem
4. Solution
5. Result
6. Tech Stack
7. Screenshots or Demo

이 구조를 쓰면 각 프로젝트 상세 페이지의 정보 깊이는 유지하면서도, 방문자가 같은 방식으로 내용을 훑을 수 있습니다.

예상 변경:

- `src/projects/mannequin/index.html`
- `src/projects/ddib/index.html`
- `src/projects/pollin/index.html`
- `src/career/Gridsol_SCADA/index.html`

### 3. 카드 레이아웃을 줄이고 섹션 레이아웃으로 전환

현재 상세 페이지는 `project-detail-card`를 많이 사용합니다. 이 방식은 안전하지만, 페이지 전체가 카드 묶음처럼 보여 메인 페이지와의 연결감이 약합니다.

추천:

- 핵심 요약과 기술 스택만 카드 형태 유지
- 긴 텍스트 섹션은 카드 대신 구분선과 여백 중심으로 구성
- 두 칼럼 레이아웃은 유지하되, 사이드바는 `Role / Stack / Links` 요약 패널로 고정

예상 변경:

- `.project-detail-section__grid`
- `.project-detail-card`
- 신규 클래스 예시:
  - `.project-detail-layout`
  - `.project-detail-main`
  - `.project-detail-sidebar`
  - `.project-detail-block`
  - `.project-detail-facts`

### 4. 메인 페이지와 톤 맞추기

현재 메인 페이지는 흰 배경, 절제된 색상, 기술 스택 칩, 이미지 썸네일이 중심입니다.

상세 페이지도 다음 기준으로 맞추는 것이 좋습니다.

- 배경 그라데이션은 약하게 줄이거나 흰 배경 중심으로 변경
- 카드 radius는 현재 2.4rem보다 낮춰 메인 썸네일과 더 가깝게 조정
- 버튼은 `cta-btn--hero` 중심으로 통일
- 기술 스택 칩은 이미 정리한 공통 스타일 유지
- 갤러리 이미지는 메인 페이지 썸네일과 같은 그림자/보더 기준 적용

예상 변경:

- `src/sass/sections/_projects.scss`

### 5. 프로젝트별 내용 리듬 정리

프로젝트 상세 페이지별로 강조 포인트를 다르게 가져가는 것이 좋습니다.

Mannequin:

- 멀티플레이 세션 흐름
- 로딩 UX
- GitLab Runner / Unity 라이선스 / 협업 자동화
- 인프라 주 담당이라는 역할을 더 선명하게 강조

DDIB:

- 프론트엔드 사용자 흐름
- 좌석 상태 확인, 선택, 예매, 교환 플로우
- API 연동과 화면 안정화
- 갤러리 비중을 조금 더 키워 실제 화면 중심으로 설명

Pollin:

- AI 설문 디지털화 흐름
- 입력 -> 구조화 -> 분석 결과 확인
- OpenAI API, Django, Vue 연결 구조
- 현재 상세 내용이 짧으므로 문제/해결/결과 문단 보강 가능

Gridsol SCADA:

- 운영 환경 경험
- HMI 작화, 자동 운전, 장애 대응
- 현장 문제를 시스템 개선으로 연결한 경험
- 포트폴리오의 차별점으로 별도 Career Detail 톤 유지

- 반응형 그리드 기준 정리

예상 영향:

- 모든 상세 페이지의 시각적 톤 변경
- HTML 구조 변경 전에도 일부 개선 가능

### 2단계: 상세 페이지 공통 HTML 구조 적용

작업 파일:

- `src/projects/mannequin/index.html`
- `src/projects/ddib/index.html`
- `src/projects/pollin/index.html`
- `src/career/Gridsol_SCADA/index.html`

예상 내용:

- 히어로 구조 통일
- 본문 섹션 순서 통일
- 사이드바 요약 패널 추가
- 기술 스택 위치와 형태 통일
- 버튼/외부 링크 위치 통일

예상 영향:

- 상세 페이지 간 일관성이 크게 좋아짐
- 유지보수 시 각 페이지를 같은 방식으로 수정 가능

### 3단계: 콘텐츠 보강

작업 파일:

- 각 상세 페이지 HTML

예상 내용:

- Pollin 상세 설명 보강
- DDIB 상세 설명을 갤러리 중심으로 재배치
- Mannequin의 인프라/세션/로딩 경험을 더 명확히 분리
- Gridsol은 개발 프로젝트와 다른 운영 경험으로 차별화

예상 영향:

- 포트폴리오의 설득력 증가
- 단순 기술 나열보다 "문제 해결 경험" 중심으로 전달 가능

### 4단계: 검증

예상 검증:

```bash
npm run build
```

추가 확인:

- 메인 페이지에서 각 상세 페이지로 이동
- 상세 페이지에서 `포트폴리오로 돌아가기` 동작 확인
- 모바일 폭에서 텍스트/버튼/이미지 겹침 확인
- DDIB 갤러리 이미지 로딩 확인
- 기술 스택 아이콘 크기 통일 확인

## 리팩터링 시 예상 결과

작업 후 기대되는 모습:

- 메인 페이지와 상세 페이지의 시각적 연결감이 좋아짐
- 상세 페이지가 더 정돈된 포트폴리오 문서처럼 보임
- 프로젝트별 역할, 문제, 해결, 결과가 더 빠르게 읽힘
- 기술 스택과 메타 정보가 더 깔끔하게 스캔됨
- 추후 프로젝트 추가 시 같은 구조를 복사해 확장 가능

## 작업 난이도

난이도: 중간

이유:

- 프레임워크 변경은 필요 없습니다.
- 기존 HTML/SCSS 구조 안에서 처리 가능합니다.
- 다만 상세 페이지 4개를 모두 손봐야 하므로 단순 스타일 수정보다는 범위가 큽니다.
- 콘텐츠 문장까지 정리하면 디자인 작업보다 시간이 조금 더 걸릴 수 있습니다.

## 예상 작업 순서

1. 상세 페이지 공통 레이아웃 SCSS 작성
2. DDIB 상세 페이지에 먼저 적용해 기준 화면 만들기
3. Mannequin 상세 페이지 적용
4. Pollin 상세 페이지 콘텐츠 보강 및 적용
5. Gridsol Career 상세 페이지 적용
6. 빌드 및 로컬 확인
7. 필요하면 메인 페이지 프로젝트 카드와 상세 페이지의 용어/버튼 라벨까지 최종 통일

## 작업 범위에서 제외해도 되는 것

이번 리팩터링에서는 아래 항목은 제외하는 것을 추천합니다.

- React/Vue 등 프레임워크로 전환
- CMS 도입
- 페이지 라우터 도입
- 대규모 애니메이션 추가
- 디자인 시스템 전체 재작성
- 프로젝트 데이터 JSON화

현재 프로젝트 목적이 개인 포트폴리오 정적 사이트이므로, HTML과 SCSS 안에서 정리하는 방식이 가장 현실적입니다.

## 최종 제안

바로 리팩터링을 진행한다면 DDIB 상세 페이지를 먼저 기준 화면으로 잡는 것을 추천합니다.

DDIB는 기술 스택, 기여 내용, 스크린샷 갤러리가 모두 있어 상세 페이지 레이아웃을 검증하기 좋습니다. DDIB에서 레이아웃이 안정되면 Mannequin, Pollin, Gridsol에 같은 구조를 적용하는 방식이 가장 안전합니다.
