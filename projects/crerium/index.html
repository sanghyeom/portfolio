Crerium

인천 영종도 파충류샵 '크레리움'의 브랜드 홈페이지를 개인 사이드 프로젝트로 기획·개발했습니다. 기획, React/Canvas 프론트엔드, FastAPI 백엔드, 배포·운영을 혼자 맡았고 지금도 crerium.r-e.kr에서 실제로 운영 중입니다.

  • 2026.10 ~ 운영 중
  • 기획 · Frontend · Backend · Infra
  • React · TypeScript · Vite · Anime.js
  • FastAPI · PostgreSQL · Docker · Caddy

Overview

Crerium은 크레스티드 게코 분양을 중심으로 파충류·양서류 용품 판매, 반려동물 호텔링, 증명사진 촬영을 함께 하는 매장 '크레리움'의 브랜드 홈페이지입니다. 운영에 필요한 문제를 찾다가 시작한 개인 사이드 프로젝트이고, 그 전에는 네이버 블로그, 스마트스토어, 카카오톡 오픈채팅에 정보가 흩어져 있었습니다.

기획, React/Canvas 기반 프론트엔드, FastAPI 백엔드, Docker 배포, 운영을 전부 혼자 진행했습니다. 매장 운영자는 완성된 관리자 페이지에서 공지와 판매 품목을 직접 올립니다.

My Role & Scope

  • 사이트 기획

    서비스 구조(공지·호텔·사진관·판매·오시는 길)와 Hero 연출, 색상·타이포그래피를 기획 문서로 정리한 뒤 구현했습니다.

  • Hero / 모션 구현

    잎 사진으로 화면을 덮고 스크롤에 맞춰 갈라지는 Hero 연출을 React + <canvas>로 구현했습니다.

  • FastAPI 백엔드 & 관리자 기능

    공지·판매 품목·매장 정보 API와 관리자 인증(Argon2, 계정 잠금, 강제 비밀번호 변경)을 구현했습니다.

  • 배포 & 운영

    Docker Compose로 DB·API·수집기·웹 서버를 구성하고, 개인 미니PC에 무료 도메인으로 직접 호스팅하며 운영하고 있습니다.

System Architecture

1. Frontend · Hero 렌더링

React + Vite + TypeScript SPA이고, Hero의 잎은 DOM이 아니라 <canvas> 한 장에 그립니다. 화면 크기에 맞춰 약 170장을 배치하고, 깊이 3단계로 흐림·명도를 한 번만 구워 둔 스프라이트를 매 프레임 회전·이동만 시킵니다. Anime.js는 이 캔버스 렌더링 자체보다는 스코프·스크롤 유틸리티 쪽에 씁니다.

2. Backend · 인증과 데이터

FastAPI + PostgreSQL(Alembic 마이그레이션 5개) 기반으로 공지·판매 품목·매장 정보 API와 관리자 인증을 구현했습니다. 관리자 경로는 환경변수로 바꿀 수 있게 했지만, 실제 접근 제어는 Argon2 해시와 세션 쿠키 쪽에 있습니다 (Engineering Challenges 참고).

3. Collector · 배포

별도 collector 컨테이너가 매일 새벽 유튜브 RSS를 확인해 같은 DB에 글을 씁니다. db·api·collector·web 네 컨테이너를 Docker Compose로 묶고, Caddy가 HTTPS 발급까지 자동으로 처리하도록 구성해 개인 미니PC에서 운영합니다.

Engineering Challenges

1. Hero를 DOM이 아니라 canvas에 그린 이유

Challenge

잎 하나하나를 div로 만들어 CSS transform으로 움직이는 방법을 먼저 시도했는데, 화면을 덮을 만큼(170장 안팎) 깔면 리플로우·페인트 비용이 바로 체감됐습니다.

Solution

잎 이미지 5종을 깊이 3단계로 한 번씩만 흐림·명도 처리해 오프스크린 캔버스에 구워 두고, 매 프레임은 위치·회전 값만 다시 계산해 그리는 방식으로 바꿨습니다. 포인터가 잎을 밀어내는 반응도 DOM 이벤트가 아니라 캔버스 좌표 계산으로 처리하고, prefers-reduced-motion이 켜져 있으면 이 레이어 자체를 만들지 않습니다.

2. 유튜브 수집: API 키 없이, 중복 없이

Challenge

채널에 새 영상이 올라올 때마다 수동으로 사이트에 등록해주는 건 비개발자인 매장 운영자에게 번거로운 일이었고, 수집기를 여러 번 돌리면 같은 영상이 중복 저장될 수 있었습니다.

Solution

유튜브 Data API 키 대신 채널의 공개 Atom RSS를 직접 파싱하고, (source, external_id) 조합으로 이미 저장된 글인지 먼저 확인해 중복을 막았습니다. 여러 인스턴스가 겹쳐 돌 가능성은 Postgres pg_try_advisory_lock으로 막았고, 수집은 cron이 아니라 컨테이너 안 파이썬 루프가 매일 한국 시간 06:00을 계산해 그때까지 자고 있다가 실행하는 방식입니다.

3. 관리자 인증 — "경로 숨기기"가 실제로 하는 일

Challenge

비개발자인 매장 운영자가 공지·상품·매장 정보를 직접 고칠 수 있어야 했지만, 그만큼 계정이 뚫리지 않게 하는 것도 중요했습니다. 관리자 주소를 추측하기 어렵게 바꾸는 것만으로는 충분하지 않았습니다.

Solution

Caddy 설정에서 관리자 화면 주소를 직접 요청하면 404와 함께 X-Robots-Tag: noindex, nofollow를 돌려주지만, 이건 검색엔진 노출을 막는 정도일 뿐 실제 접근 제어는 아닙니다. 진짜 인증은 FastAPI 쪽에 있습니다 — 비밀번호는 Argon2로 해시하고, 존재하지 않는 아이디로 로그인해도 더미 해시와 같은 비교 연산을 수행해 응답 시간으로 계정 존재 여부를 유추할 수 없게 했습니다. 5번 틀리면 15분 잠기고, 세션 토큰은 평문이 아니라 SHA-256 해시로 저장되며 쿠키는 HttpOnly·SameSite=Strict로 묶었습니다. 계정을 처음 발급하면 비밀번호를 바꾸기 전까진 다른 관리 기능을 쓸 수 없고, 동시 로그인 실패로 계정이 잠기는 경우까지 포함해 pytest로 테스트해 뒀습니다 (backend/tests/test_auth.py, 591줄).

Technical Highlights

  • canvas 기반 Hero 모션

    잎 ~170장을 3단계 깊이로 구워 둔 캔버스 한 장에 그리고, 스크롤·포인터에 반응해 비바리움을 드러냅니다.

  • 중복 없는 유튜브 자동 수집

    Atom RSS 직접 파싱, (source, external_id) 중복 확인, advisory lock으로 매일 06:00(KST)에 안전하게 수집합니다.

  • Argon2 기반 관리자 인증

    계정 잠금, 세션 해시 저장, 강제 비밀번호 변경까지 포함한 인증 흐름을 pytest로 검증해 두었습니다.

  • Docker Compose 4-서비스 운영

    db·api·collector·web을 한 번에 띄우고, Caddy가 HTTPS 발급까지 자동으로 처리합니다.

  • 무료 도메인 + 개인 서버 호스팅

    상용 호스팅 비용 없이 개인 미니PC 위에서 실제 서비스로 운영 중입니다.

Result & Retrospective

Result

crerium.r-e.kr은 실제로 접속되는 상태이고, 매장 운영자가 관리자 페이지에서 공지·품목·매장 정보를 직접 올립니다. 수집기는 채널에 새 영상이 올라오면 다음날 새벽 자동으로 목록에 추가합니다.

Impact

블로그·스마트스토어·오픈채팅에 나눠져 있던 정보를 하나의 브랜드 홈페이지로 모았고, 공지나 상품 정보가 바뀌어도 개발자 없이 관리자 페이지에서 직접 갱신할 수 있습니다.

Retrospective

기획 문서(BRIEF.md) 초안에는 비바리움 내부를 눌러 설명을 보여주는 '들여다보기' 섹션과 개체 6마리를 카드로 보여주는 섹션이 있었는데, 지금 공개된 화면에는 둘 다 없습니다. 코드에는 Explore.tsx, Geckos.tsx가 그대로 남아 있어, 구현은 해 두고 이번 공개 범위에서는 뺀 것으로 보입니다 — 처음 잡은 기획을 끝까지 구현하는 것보다, 실제로 필요한 화면부터 먼저 올리는 쪽으로 우선순위를 바꾼 셈입니다. 이후에는 분양·예약 신청 이력 관리, 방문자 통계까지 확장해 보고 싶습니다.
